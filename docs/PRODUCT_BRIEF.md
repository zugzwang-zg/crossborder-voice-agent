# CrossBorder Voice 产品简报

## 1. 一句话定义

CrossBorder Voice 是一个面向跨境电商运营人员的双语消费者洞察原型：把英语和西班牙语评论转换为带分母、证据和适用范围的行动候选，帮助人更快完成筛选、比较与复核。

## 2. 问题与机会

星级、词云和通用正负面分类可以描述总体情绪，但无法直接回答：

- 产品、包装、履约和使用体验分别出了什么问题；
- 哪些正面表达可以作为待验证的卖点；
- 英语与西语样本的关注点有什么差异；
- 一项建议由多少记录支持，原文证据在哪里；
- 运营人员下一步应找哪个负责人、验证什么假设。

人工阅读能够理解上下文，但难以稳定处理大量双语评论。机会不是“让模型替人决策”，而是让模型先完成一致的结构化整理，并把证据和边界交还给人。

## 3. 目标用户与 JTBD

### 主要用户

- 产品运营：识别产品体验和预期落差，形成改进假设；
- 内容运营：从高星证据中提炼待验证卖点和内容主题；
- 客服运营：区分产品、履约与使用指导问题，整理 FAQ 候选。

### Jobs to be done

> 当我复盘一批来自不同语言的消费者评论时，我希望快速定位高频问题与潜在卖点，并能回到原文检查依据，从而把有限时间投入到验证和协调，而不是反复整理表格。

## 4. 核心使用路径

1. 选择语言、星级、情感或问题范围；
2. 查看洞察排序、支持量、样本分母和限制；
3. 打开代表性评论，核对被引用的原文片段；
4. 将行动候选路由到产品、页面、履约、客服或内容；
5. 人工记录负责人、优先级、状态和备注，导出反馈日志。

## 5. MVP 范围

| 维度 | 当前范围 |
|---|---|
| 数据 | MARC 历史公开语料，英语 500 条、西语 500 条 |
| 抽样 | 每个“语言 × 1—5 星”组合 100 条的确定性分层样本 |
| 标签 | 情感、属性、问题、购买动机、场景、预期落差、言语行为与原文证据 |
| 输出 | 15 条可追溯洞察、证据库、跨语言对比和行动候选 |
| 交互 | 筛选、排序、搜索、分页、证据高亮、状态/负责人/备注和反馈导出 |
| 评测 | 100 条冻结测试集；另有 40 条待双人标注的挑战输入 |

### 明确不做

- 不把西语语料自动映射为某个国家或文化群体；
- 不用 2015—2019 年语料声称当前市场趋势；
- 缺少商品标识时不输出单品级结论；
- 不将模型 `confidence` 解释为正确概率；
- 不把 AI 预评审冒充独立人类评测；
- 不自动执行改价、改页面、回复客户等外部业务动作。

## 6. 功能优先级

| 优先级 | 能力 | 原因 |
|---|---|---|
| P0 | Schema、标签白名单、原文证据与数据范围校验 | 没有可信输入就不应生成业务建议 |
| P0 | 洞察支持量、分母、语言分布与来源 ID | 让运营人员知道结论基于什么 |
| P0 | Dashboard 筛选与证据回查 | 形成可体验、可复核的核心闭环 |
| P1 | 行动负责人、优先级、状态和反馈导出 | 把“发现”连接到人工工作流 |
| P1 | 冻结测试集与回归评测 | 支持可重复的模型迭代 |
| P2 | 新数据源、商品/站点/时间字段 | 进入单品或市场趋势判断前的必要条件 |
| P2 | 人工与 AI 辅助耗时对照实验 | 验证效率价值，而不是只验证模型指标 |

## 7. 验收标准

- 公开演示无需 API Key，可用安全样本完成核心路径；
- 不合规 JSON、无依据标签或越界证据不能进入聚合；
- 每条正式洞察可回到支持记录和代表性原文；
- 筛选条件、排序、分页和证据高亮有自动化测试；
- 评测报告同时展示收益、退化、逐类指标和样本限制；
- 公开仓库不包含密钥、完整原始语料、逐条模型输出或人工复核工作簿；
- 发布候选通过测试、依赖/资产审计和范围明确的 AI 预评审。

## 9. 发布定义

v0.2.0 是一个可公开体验、可复现并通过范围审查的方法验证版本。它证明了“从双语评论到可追溯行动候选”的产品链路，但不证明真实业务增长、生产稳定性或跨市场普适性。
