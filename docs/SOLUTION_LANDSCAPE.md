# 方案对比与产品定位

本文件比较解决同一类任务的工作方式，而不是对具体厂商做功能或价格排名。平台能力会变化，选型前仍需基于真实数据重新验证。

## 目标任务

将一批英语与西班牙语评论整理为可复核的产品、内容、履约和客服行动候选。

| 方案 | 优势 | 主要缺口 | 更适合的场景 |
|---|---|---|---|
| 人工阅读 + 表格 | 语境理解强、工具门槛低、结论可直接讨论 | 双语批量处理慢；口径易漂移；证据与统计需要手工维护 | 小批量、高风险、需要深度定性研究 |
| 通用 LLM 对话 | 启动快、探索灵活、适合快速总结与脑暴 | 输入和提示难复现；分母、来源和版本记录不足；容易生成无证据建议 | 早期探索、一次性摘要、低风险辅助 |
| 通用 VOC / 文本分析平台 | 数据连接、看板、权限和持续监控通常更成熟 | 自定义语言学标签、证据边界和离线复现能力取决于平台；采购与集成成本更高 | 已有持续数据流和成熟运营团队的生产场景 |
| CrossBorder Voice | 双语标签可控；输出绑定原文、分母和范围；评测与版本可复现；公开演示无需 API | 当前数据历史较久、无商品标识；不具备生产级连接器、权限与实时监控 | 需要验证方法、演示产品思路或构建定制工作流原型 |

## 差异化取舍

CrossBorder Voice 不追求覆盖完整 VOC 平台，而是把以下能力做深：

1. **证据优先：** 标签和洞察必须能回到原文；
2. **范围优先：** 展示抽样分母和数据限制，不把样本差异外推成市场事实；
3. **决策路由：** 将发现映射到产品、页面、履约、客服和内容负责人；
4. **可复现评测：** 固定输入、配置、提示版本和输出契约；
5. **安全公开：** 演示数据与正式/私有评审材料分离。

## Build / buy / manual 判断

- **继续人工：** 每月样本很小、问题高风险、定性深度比处理速度更重要；
- **采购平台：** 已有稳定多渠道数据、组织权限要求和持续监控需求；
- **定制原型：** 标签体系、证据边界或运营流程具有明显业务特异性，需要先验证再决定采购或建设；
- **混合方案：** 平台负责采集和监控，定制链路负责特定标签、证据审查和决策路由。

当前项目选择“定制原型”，因为目标是验证可追溯双语洞察链路，而不是替代成熟生产平台。
