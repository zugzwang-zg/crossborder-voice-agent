## 开发与独立评测

- 新开发集覆盖多主题长评论、隐含属性、西语口语、正负混合表达、未使用与履约评价边界；给每个样本标注来源、语言、任务类型和最小证据片段。
- 将既有失败案例仅用于开发。新测试集按语言和主要标签分层，由两名评审者分别标注，分歧仲裁前保留各自记录；冻结后禁止用于提示词调整。
- 同时报 Precision、Recall、F1、各类样本数、证据语义有效率和失败率，避免只改善 Precision。报告新旧版本的配对差异及不确定性，稀有类样本不足时明确标注。
- 每次实验使用独立输出目录。运行指纹绑定输入、提示词、模型参数、端点、Schema 和本地校验器；旧输出不含指纹时默认拒绝续跑。

## 建议的可执行性

每条待验证建议使用以下记录结构：

| 字段 | 记录要求 |
|---|---|
| 问题与证据 | 标签、支持评论 ID、分子/分母、原文片段 |
| 具体动作 | 谁在何处修改什么；产品、履约、内容分别处理 |
| 适用条件 | 当前商品/站点是否具备对应事实；信息不足时待确认 |
| 验证指标 | 采用与否、修改次数、完成任务时间、不可执行原因 |
| 执行结果 | 负责人和实际时间；没有执行则留空，不填写预测收益 |

同批任务采用交叉顺序对比人工与辅助流程，记录实际耗时和采纳情况；不要把模型置信度解释成采纳概率。
