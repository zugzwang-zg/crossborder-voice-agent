# 产品决策日志

## 使用方式

这里记录影响产品范围、可信度和体验的关键决策。每条包含背景、选择、取舍与可观察结果，避免只展示最终界面而隐藏判断过程。

## D-01：以行动问题而不是通用情感分类定义 MVP

- **背景：** 正负面比例无法直接指导详情页、产品、履约或客服动作。
- **选择：** 增加产品属性、具体问题、购买动机、场景、预期落差和言语行为，并为行动建议设置负责人路由。
- **放弃：** 只做词云、情感占比或自动生成营销文案。
- **取舍：** 标签设计和评测成本更高，但输出更接近运营任务。
- **结果：** 正式报告形成 15 条带证据和行动候选的洞察。

## D-02：采用确定性“语言 × 星级”分层抽样

- **背景：** 随机小样本可能被某个语言或星级主导，跨语言比较也难复现。
- **选择：** 英语与西语各 500 条，每个语言 × 1—5 星组合 100 条。
- **放弃：** 将样本比例描述为市场自然分布。
- **取舍：** 便于评测和对比，但不能估计真实市场占比。
- **结果：** 所有语言/星级单元可稳定复现；README 和报告明确分母边界。

## D-03：把星级与文本情感分开建模

- **背景：** 五星评论可能“尚未使用”，低星评论也可能主要抱怨配送。
- **选择：** 星级保留为元数据，文本情感独立判断，并允许 `mixed` 与 `uncertain`。
- **取舍：** 标签体系更复杂，但减少将购买评分直接当成文本态度的误判。
- **结果：** 看板可以筛选星级—情感不一致记录并回查证据。

## D-04：不接受没有原文证据的标签

- **背景：** LLM 摘要流畅不等于结论可核验。
- **选择：** 关键标签绑定最小充分原文片段；Schema、白名单和原文包含校验共同拦截不合规输出。
- **取舍：** Recall 可能下降，流水线需要错误记录与重试机制。
- **结果：** Improved v9 的人工证据语义有效率由 88% 提升到 96%。

## D-05：优先提高属性 Precision，并公开 Recall 代价

- **背景：** 错误属性会把运营注意力导向不存在的问题。
- **选择：** 收紧标签边界和提示规则，优先减少假阳性。
- **取舍：** 隐含属性和多主题长评论仍可能漏召回。
- **结果：** 属性 Precision 从 72.22% 提升到 83.18%，F1 从 67.47% 提升到 74.02%；限制同步保留在报告中。

## D-06：采用 Next.js 证据看板，而不是只交付静态报告

- **背景：** 运营人员需要从汇总回到记录，并比较不同筛选条件。
- **选择：** 提供筛选、排序、分页、搜索、证据高亮、行动状态和反馈导出。
- **放弃：** 只提供 Notebook、CSV 或不可交互截图。
- **取舍：** 增加前端和测试成本，但让产品路径可体验。
- **结果：** 无 API Key 的公开 Demo 可以完成“筛选 → 洞察 → 证据 → 人工状态”闭环。

## D-07：公开演示数据与正式/私有数据分离

- **背景：** 作品集需要可访问，同时不能暴露完整原文、金标、逐条模型输出或密钥。
- **选择：** 公共页面默认加载 10 条安全演示样本；敏感评审材料统一保存在被忽略的 `.private/`。
- **取舍：** 在线 Demo 不展示完整 1,000 条正式明细。
- **结果：** 公开仓库可直接运行，私有材料未进入版本控制。

## D-08：AI 预评审不冒充人类评测

- **背景：** 个人项目缺少完整评审团队，但仍需要降低发布盲点。
- **选择：** 使用不同角色和模型做机械、语义、风险评审及必要仲裁；公开哈希证明，并明确标注为 AI 预评审。
- **放弃：** 将模型一致意见写成“专家评审”或“用户验证”。
- **取舍：** 能提高个人发布流程的完整性，但不能替代独立人类标签或业务验收。
- **结果：** v0.2.0 的 15 条候选全部完成范围受控的正式 AI 预评审。

## D-09：移除聚合的平均模型 confidence

- **背景：** 模型自报 `confidence` 未经校准，平均值容易被误读为正确概率或业务可信度。
- **选择：** 不再发布聚合平均 confidence；改为展示支持量、分母、语言分布、证据和限制。
- **取舍：** 少了一个看似直观的数字，但降低虚假精确感。
- **结果：** Dashboard 与报告改用可复核的支持信息解释洞察强弱。
